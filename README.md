# 记忆存活性体检包 / Memory Persistence Diagnostic

给你的 AI 工作环境做一次**只读体检**：哪些目录会随沙箱销毁、哪些能活过重启、
记忆文件落在哪里、出口网络通不通、配额给了多少。

**默认完全只读、不联网。** 报告只含路径、类型、计数与建议，不含任何文件内容，
可以放心外发。

## 它解决什么问题

办公 AI 平台的"云电脑"本质是生态内的临时沙箱：没有独立外网 IP、生命周期由平台
决定。用户以为自己在"用电脑"，其实是在租一个会随时清空的工位——聊着聊着它忘了、
沙箱销毁后记忆全丢，不是用户不会用，是结构性必然。

这个工具把"你的环境到底保不保得住你的记忆"变成一份看得懂的报告。

## 它查什么

- **持久性地图**：逐个挂载点判断"重启即失 / 疑似随实例销毁 / 通常持久 / 共享卷"
- **记忆目录盘点**：常见智能体记忆目录（`~/.memory`、`~/memories`、`~/.claude` 等）
  落在哪种卷上、里面有多少文件
- **实例信号**：运行时长（太新说明刚被重建过）、容器环境识别
- **配额**：内存上限、磁盘余量——空间紧张时智能体写记忆会静默失败
- **出口网络**（可选 `--net`）：pypi / github / huggingface / npm / openai 通不通
- **跨重启探针**（`--plant` / `--check`）：播种随机标记，重启后实测哪些目录真的能活
- **前后对比**（`--compare 旧报告.json`）：按稳定发现项 ID 对比两次体检——新增 / 已解决 / 持续

## 快速开始（2 步）

需要 Python 3.8+。**零依赖**——纯标准库。

1. 解压后指向你的项目目录（默认当前目录）：

   ```bash
   python memory_persistence_diag.py
   ```

2. 打开报告 `memory_diag_reports/memory_persistence_report.md`，先处理高危项。

可选：

```bash
python memory_persistence_diag.py --net      # 附带出口网络检测
python memory_persistence_diag.py --plant    # 重启前播种探针标记
python memory_persistence_diag.py --check    # 重启后收获，实测各目录存活情况
python memory_persistence_diag.py --compare memory_diag_reports/memory_persistence_report.json
                                             # 修复后复跑对比：新增 / 已解决 / 持续
```

## 修复验收：发现项 ID 与前后对比

每条发现带稳定 ID（如 `HOME-EPHEMERAL`、`CWD-EPHEMERAL`、`MEMDIR-VOLATILE:<路径>`、
`DISK-LOW`），并标注自修工时估计（人时）。修复后复跑并加
`--compare 上次报告.json`，报告会列出：

- ✅ **已解决**——上次有、这次没了的发现项
- 🆕 **新增**——这次才出现的发现项
- 🔁 **严重程度变化**——同一问题变好或变差
- 其余为**持续存在**，按建议继续处理

用「高危 N→0」作为修复验收标准，而不是凭感觉说"应该修好了"。

## 探针的容灾设计

`--plant` 除了在报告目录写播种记录，还会把注册表快照同步写进每个播种目录
（隐藏文件 `.memory_probe_registry.json`）。即使报告目录随沙箱销毁，
`--check` 也能从任意存活的播种目录恢复记录，完成验收。

## 不会用命令行？把这段话贴给你的 AI

在你的 AI 对话框里直接粘贴：

> 请帮我检查这个环境的记忆持久性：1) 看看当前系统有哪些挂载点，哪些是 tmpfs
> 或 overlay 这类重启会丢的；2) 检查你保存记忆的目录（比如 ~/.memory、
> ~/memories 或你实际在用的记忆位置）落在哪个挂载点上；3) 告诉我运行时长
> （uptime）和磁盘剩余空间；4. 最后用一张表告诉我：哪些东西重启会丢、哪些能留，
> 以及你建议我把长期记忆迁移到哪里。

你的 AI 跑完这几步，得到的就是本工具报告的核心结论。

## 设计铁律

1. **默认只读、不联网**——只看挂载表、系统配额和已有文件的位置。
2. **探针只写随机标记**——`--plant` 写入的标记是随机 token，不含任何用户数据；
   `--check` 验证后即删除。
3. **报告即交付物**——Markdown + JSON 双格式，只含路径、类型、计数与建议。

## 实测样例

在一个容器化沙箱（overlay 根分区 + virtiofs 共享卷）上的真实输出：

- 高危 1：工作目录在 overlay 上，实例销毁即失
- 信息 5：家目录与记忆目录在共享卷、内存配额 4 GB、磁盘余量 23 GB、实例运行 6.7 小时
- 探针收发：播种 5 处标记，收获 5 处全部原样保留

## 报告解读

发现按 🔴 高 → 🟡 中 → 🔵 低 → ⚪ 信息 排序，每条带具体建议。典型结论：

- **家目录/工作目录在 overlay 或 tmpfs**（高危）——记忆活不过实例重建，先迁移
- **记忆目录在共享卷/真实磁盘**（信息）——相对安全，用探针实测确认
- **磁盘余量低于 10%**（信息）——智能体写记忆会静默失败，及时清理

## 分享报告

把 `memory_persistence_report.md`（或 JSON）发回给我们，我们会给出针对性的
持久化改造方案：先救高危目录，再补定期备份，最后接外部记忆层。
